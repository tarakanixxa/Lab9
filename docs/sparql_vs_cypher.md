# SPARQL vs Cypher та text-to-Cypher

## 1. П'ять CQ для зіставлення
Використайте відповідні CQ з ЛР 8 (`tests/cq_sparql/`). У цій папці надано чернетки SPARQL для п'яти базових питань. Перед виконанням звірте IRI/префікс `:` та локальні назви властивостей із фактичним `models/onto.owl` / `models/onto_data.ttl` з ЛР 7. Якщо URI відрізняються, замініть їх на URI з власної онтології — не видавайте чернетку за вже перевірений запит.

| CQ | Питання | Cypher | SPARQL |
|---|---|---|---|
| CQ01 | Завод і цехи | `cq01_structure.cypher` | `cq01_workshops.rq` |
| CQ02 | Цехи й обладнання | `cq02_machines_by_workshop.cypher` | `cq02_machines.rq` |
| CQ03 | Обладнання та матеріали | `cq04_material_stock.cypher` | `cq03_materials.rq` |
| CQ04 | Продукція та дефекти | `cq05_product_defects.cypher` | `cq04_defects.rq` |
| CQ05 | Технологічні процеси та операції | `cq06_operation_chain.cypher` | `cq05_operations.rq` |

## 2. Порівняльна таблиця
| Критерій | SPARQL | Cypher |
|---|---|---|
| Читабельність | Добре описує RDF-граф через триплети | Наочно показує шлях вузол-зв'язок-вузол |
| Довжина | Часто довший через PREFIX та IRI | Часто компактніший для property graph |
| Час | Вимірюється на RDFLib/середовищі ЛР 8 | Вимірюється в Neo4j Aura |
| Зручність | Сильний для RDF/OWL та семантичних словників | Сильний для шляхів, патернів і графових операцій |
| Обмеження | Працює з RDF-триплетами; LPG-метадані треба відобразити | Не є стандартним RDF-запитом; схема та типи зв'язків задаються окремо |
| Походження | Можна моделювати через PROV-O та окремі вузли/триплети | Зручно зберігати `source`, `confidence`, `validFrom` на ребрах |

Заповніть фактичні часи та порівняйте множини результатів. Якщо є різниця, перевірте різницю моделювання, неповноту індивідів або типізацію.

## 3. Text-to-Cypher
`tests/text_to_cypher.py`:
- додає схему в системний prompt;
- використовує список дозволених міток/типів;
- відхиляє запити, що не починаються з MATCH/WITH/UNWIND/RETURN;
- блокує write/admin keywords;
- вимагає LIMIT;
- виконує через read transaction (`execute_read`), а не write transaction.

Для повноцінного LLM-режиму встановіть `OPENAI_API_KEY` і `OPENAI_MODEL`. Якщо ключ не задано, скрипт використовує демонстраційні шаблони для 10 питань; це тестовий режим, а не оцінка генеративної моделі.

## 4. Метрики
Коректність = кількість запитів, що пройшли синтаксичну перевірку, схему та виконання / загальна кількість запитів × 100%.
Час вимірюється `time.perf_counter()` від початку генерації до завершення виконання.
Після запуску збережіть `tests/t2c_results.jsonl`. Три помилки проаналізуйте за фактичними логами. Не вигадуйте помилки, якщо всі 10 успішні: для аналізу використайте контрольні негативні тести й позначте їх окремо.
